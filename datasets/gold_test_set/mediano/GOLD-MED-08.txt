TITULO: Aprovisionamiento Automatizado y Declarativo de Infraestructura como Código (IaC) en AWS mediante Terraform
CATEGORIA_ESPERADA: DevOps

Desafíos de la Gestión de Infraestructura Manual (ClickOps):\nHistóricamente, el aprovisionamiento de servidores, redes y bases de datos a través de la consola gráfica de la nube (AWS Management Console) generaba entornos de desarrollo (Dev, Staging, Prod) que divergían sutilmente entre sí. Estos cambios no documentados (Configuration Drift) convertían la infraestructura de AyniKortex en sistemas inmanejables, provocando tiempos de caída extensos durante los despliegues de nuevas versiones de software y dificultando las auditorías de seguridad perimetral.\n\nTransición a Infraestructura como Código (IaC) Modular:\nPara resolver esto, el equipo de plataforma estandarizó el despliegue a través de Terraform. Esta herramienta permite describir, de forma declarativa e idempotente, toda la topología de la nube utilizando código HCL (HashiCorp Configuration Language). Se estructuraron módulos reutilizables para aprovisionar Virtual Private Clouds (VPCs) segmentadas, subredes aisladas, Gateways de NAT, políticas granulares IAM, y clústeres de base de datos RDS. Todos los cambios son versionados en repositorios Git y sujetos al mismo rigor de Pull Requests que el código fuente tradicional.\n\nFlujos de Trabajo CI/CD y Control de Estado Remoto:\nEl verdadero poder operativo se materializa en el pipeline de automatización. Durante un cambio de código IaC, GitHub Actions ejecuta automáticamente comandos `terraform validate` y `terraform plan`, permitiendo a los ingenieros visualizar en un documento las adiciones y destrucciones exactas de recursos. El estado del sistema (State File) se asegura remotamente en buckets S3 encriptados con bloqueos atómicos en DynamoDB, garantizando que el `terraform apply` final aprovisione la arquitectura en AWS de manera auditable, segura y sin intervención humana de la consola web.
